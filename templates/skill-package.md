# Skill 包规范

这是贡献者的接入参考，不是可安装 Skill。仅在实现具备完整流程时创建 `skills/maige-<task>/SKILL.md`。

## SKILL.md 应包含

- 元信息：唯一的 `name`、说明使用时机的 `description`。
- 任务与边界：做什么、不适合什么任务。
- 输入：最低必要信息、可选配置、材料不足时如何处理。
- 运行条件：工具、版本、依赖、网络、权限和费用来源。
- 流程：理解材料、生成、预览、修改、导出及失败处理。
- 输出：文件格式、位置、源文件、成品以及可编辑范围。
- 验证：有用的验收方法与实测证据；不把自述当作兼容性证明。
- 最小示例：可独立执行，并可进行一次修改。

## README.md 应包含

当前状态、实际交付、已测试环境、安装方式、最短样例、替换自己的材料、修改与重新生成、依赖与成本、已知限制、来源与许可。

## 包设计原则

保持主 Skill 指导简洁，长篇参考资料放在 `references/`；实际执行入口放在 `scripts/`；运行工程、模板和最小样例放在 `assets/`。只创建用得到的目录。

一个组件不等于一个 Skill。优先按用户任务封装，让 Agent 选择合适的组件。不要依赖未打包的共享文件，也不要把私有内部生产规范作为外部用户必须遵守的前提。
